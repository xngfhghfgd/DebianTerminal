# DebianTerminal

Run a **real Debian GNU/Linux 12 (bookworm) ARM64** on your iPhone/iPad — a
genuine `root@debian:~#` with systemd, bash, apt and a persistent disk — driven
entirely from an iOS 26.1 app. No jailbreak, no proot, no Termux, no BusyBox,
no compatibility layer, no faked `/etc/os-release`.

```sh
$ uname -a
Linux debian 6.1.0-53-arm64 #1 SMP Debian 6.1.187-1 (2026-09-07) aarch64 GNU/Linux
$ cat /etc/os-release
PRETTY_NAME="Debian GNU/Linux 12 (bookworm)"
VERSION_ID="12"
VERSION_CODENAME=bookworm
ID=debian
$ cat /etc/debian_version
12.15
```

## How it works

The full chain (all real, no shims):

```
iOS app (SwiftUI)
  └─ spawns qemu-system-aarch64  (built for iOS, arm64, TCG JIT)
       └─ -machine virt  (QEMU AArch64 machine)
            └─ ARM64 Linux kernel (6.1.0-53-arm64)  ← -kernel Image
                 └─ official Debian 12 arm64 rootfs  ← /dev/vda (VirtIO ext4)
                      └─ systemd (PID 1)
                           └─ serial-getty on ttyAMA0
                                └─ bash → root@debian:~#
```

- **JIT**: QEMU's **TCG** translates guest ARM64 instructions to host ARM64
  code at runtime. This requires the iOS JIT entitlements + Developer Mode. See
  [`Docs/JIT.md`](Docs/JIT.md).
- **Machine**: `virt`, `-cpu max`, `-smp 2`, `-m 2048` (all configurable).
- **Storage**: a persistent raw ext4 disk (`debian12.img`, 8 GiB default) on a
  VirtIO block device. Packages, `/etc`, `/home` and apt caches survive restarts.
  The app keeps the image in `Documents/Debian/debian12.img` and never repacks
  it; the `debian12.img` produced by `build-debian.sh` is copied there once
  (via Files app / the app's import) rather than bundled, to keep the app small.
- **Networking**: VirtIO NIC + QEMU user-mode (slirp), so DHCP + DNS work out of
  the box (guest DNS = `10.0.2.3`).
- **Console**: PL011 UART (`ttyAMA0`) wired to the app's PTY terminal.

## Building the guest (Linux)

The three `Scripts/*.sh` produce `Image`, `initrd.img` and `debian12.img`. You
can run them on any Linux host with kernel/loop/binfmt support. They were
developed and validated on Debian 12 x86_64 (cross-arch, arm64 guest).

```sh
# 1. Debian rootfs + kernel + initramfs + persistent disk
sudo ./Scripts/build-debian.sh            # 8 GiB disk; MIRROR/DISK_SIZE overridable
# 2. (optional) just the kernel
./Scripts/build-kernel.sh                 # or: ./build-kernel.sh --source 6.7
```

`build-debian.sh` handles the hard parts that make a cross-arch Debian actually
boot on `virt`:

- stages `debootstrap` in a **space-free** temp dir (a path with spaces breaks
  the package index resolution),
- installs `linux-image-arm64` + initramfs, sets `MODULES=list` and puts the
  `virtio*`/`ext4` drivers **inside** the initramfs (the stock `MODULES=most`
  is unusably slow under qemu-user, `MODULES=dep` cannot probe a device),
- writes `fstab` (`/dev/vda` root), hostname, USTC apt sources,
- enables `serial-getty@ttyAMA0` and `systemd-networkd`, and configures the NIC
  (matched by `Name=enp* eth*` — the real name is `enp0s2`, not `eth0`),
- sets `root:debian`,
- builds a raw ext4 disk and copies the rootfs into it **excluding** the
  bind-mounted `proc/sys/dev/run/tmp`,
- prints the exact boot command.

> The disk image is what makes the app "persistent". The app points at its own
> copy of `debian12.img` in `Documents/Debian/` and never repacks it.

### Boot it (Linux, to reproduce the POC)

```sh
qemu-system-aarch64 -machine virt -cpu max -smp 2 -m 2048 \
  -kernel Image -initrd initrd.img \
  -drive file=debian12.img,if=none,id=disk0,format=raw \
  -device virtio-blk-pci,drive=disk0,romfile= \
  -netdev user,id=net0 -device virtio-net-pci,netdev=net0,romfile= \
  -append "root=/dev/vda rw console=ttyAMA0" -nographic -no-reboot
```

(`romfile=` on the virtio devices is required — the host lacks `efi-virtio.rom`.)

## Building QEMU for iOS (the on-device emulator)

`Scripts/build-qemu.sh` cross-builds `qemu-system-aarch64` for
`aarch64-apple-ios`. It requires macOS + the Xcode iOS SDK (this is why the
**iOS** build must run on a Mac, not here). It builds `glib` + `pixman` for iOS,
configures QEMU with `--cross-file` for the iOS target and `--target-list=aarch64-softmmu --enable-tcg`,
and documents the saved-JIT slices. See the script header and `Docs/JIT.md`.

## Running the iOS app

1. `brew install xcodegen && xcodegen generate` to produce `DebianTerminal.xcodeproj`
   from `project.yml` (the source of truth). `project.yml` was written by hand
   and is what defines the file set; regenerate after adding/removing sources.
2. Set your Apple **Developer Team** in the Signing pane (project.yml leaves
   `DEVELOPMENT_TEAM` empty), and set device signing (personal team is fine).
3. Drop the runtime artifacts into `Resources/` so they are packaged:
   `qemu-system-aarch64`, `Image`, `initrd.img`, `debian12.img`. (The app can
   also be pointed at files in its `Documents/Debian/` dir via Settings.)
4. **Enable Developer Mode** on the device
   (`Settings → Privacy & Security → Developer Mode`); it grants the JIT and
   subprocess entitlements.
5. Build & run on a real iOS 15+ device (arm64). The simulator enables JIT by
   default, but a device requires the entitlements.

The app's Settings screen lets you choose CPU (1/2/4) and RAM (1024/2048/4096
MB); the kernel command line, disk/kernel/initrd names, network toggle and
shutdown timeout are all in `VMConfig`. Everything is persisted to
`Documents/Debian/config.json`.

## Configuration reference (`VMConfig`)

| Field | Default | Notes |
|-------|---------|-------|
| `cpuCount` | `2` | 1 / 2 / 4 |
| `memoryMB` | `2048` | 1024 / 2048 / 4096 |
| `machine` | `virt` | QEMU AArch64 `virt` |
| `cpuModel` | `max` | `-cpu max` |
| `kernelCommandLine` | `root=/dev/vda rw console=ttyAMA0` | |
| `diskImageName` | `debian12.img` | persistent ext4 |
| `kernelName` / `initrdName` | `Image` / `initrd.img` | |
| `networkEnabled` | `true` | VirtIO net + slirp |
| `shutdownTimeoutSeconds` | `10` | graceful `shutdown -h now` before SIGKILL |

## Validation

See [`Docs/POC_VERIFICATION.md`](Docs/POC_VERIFICATION.md) for the live,
machine-verified results on the dev host: real aarch64 kernel, Debian 12.15,
systemd PID 1, bash at `root@debian:~#`, serial console login, apt + network,
and disk persistence across a reboot.

### Honest scope

- The **guest chain is fully verified** on the Linux dev host.
- The **iOS app source** is authored and reviewed here but **not compiled/run**
  (no macOS/Xcode on this host). The QEMU-for-iOS cross-build and the app build
  must be validated on a Mac with Xcode + Developer Mode device.
- QEMU full-system TCG emulation on a phone is slow; expect usable but not
  native performance.
